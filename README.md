# GPT2WEB 圖片收藏室

[開啟網站](https://pfgcg01.github.io/GPT2WEB-gallery/)。首次請使用擁有者提供的完整專用連結；專用連結包含圖庫操作權限，請自行保管。

網站可查看圖片、GIF、影片、音訊、3D 與已同步的文字研究。可按主題、服務商、模型、批次等條件挑選，保存喜歡／封存及分類結果。

## 編號媒體與 TXT 批次上傳

1. 將同一批媒體及 TXT 放在同一個資料夾。
2. 網站按「批次上傳」→「加入整個資料夾」。Firefox 詢問是否允許讀取整個資料夾時，按「Upload」；網站會先讀取檔案與對照資料。
3. 查看「已載入／解析／已套用 N／N」。展開「個別資料與調整」，檢查模型、完整 Prompt 及來源；沒有提供的欄位可留空。
4. 按網站的「開始批次上傳」，才開始傳送媒體並加入圖庫。
5. 若斷線或重新整理，回到批次上傳，按「繼續／重試未完成檔案」。待傳原檔與 TXT 對照保存在目前瀏覽器；成功項目不重傳。資料仍在待傳時請保留本機原檔及瀏覽器資料。

也可用「選擇檔案與 TXT」同時多選，或先選媒體再按「載入 TXT／MD／JSON 對照檔」。不同服務商都有 01、02 時，請分批選資料夾，或在對照中寫明來源與相對路徑。

TXT 範例：

```text
01
模型：使用的模型名稱
來源：服務商名稱
Prompt：第一張的提示詞。
可有多行內容。

02 另一個模型名稱
Prompt：第二張的提示詞。

03~06
Prompt：第三至第六張共用這段提示詞。
```

可以直接用 `01`、`02 模型名稱`、`01~10`、`13-16` 或 `[01.png]` 作為區段；共用 Prompt 可和各編號模型合併。`11.12-Lovable_01.txt` 這類對照檔名可讀出服務商，資料夾路徑亦可提供來源。網站依檔名／編號配對，不會看圖猜模型或補出不存在的 Prompt。手動調整過的資料不會被後續 TXT 覆蓋；衝突或無法配對會提示。

## 檔案與播放

媒體支援 PNG、JPG、WebP、GIF、MP4、WebM、WAV、MP3、FBX、GLB、GLTF。單檔最多 50 MiB，每批最多 100 檔／512 MiB；TXT／MD／JSON 作為對照，不是另存的媒體，每份最多 5 MiB。

MP4 在目前瀏覽器無法解碼、但能讀到封裝尺寸時，網站可用通用縮圖繼續上傳並提示。原片保留，不會自動轉碼；可下載後用支援該編碼的播放器觀看。

## 文字研究

已配對外掛的文字研究，在「文字研究成果」可閱讀最終正文、各階段及來源，並下載已同步的 HTML／Markdown／TXT 原報告。外掛 v1.3.2 支援研究報告原檔直接存入私人 GitHub；更新後保留原配對，舊待傳報告可重試同步。

## 資料位置

- 本儲存庫只提供 GitHub Pages 網站介面，不保存管理密鑰。
- 媒體原檔與預覽經 Cloudflare 直接寫入公開的 [Novel-1234/GEN-IMG](https://github.com/Novel-1234/GEN-IMG)。公開媒體本身可直接讀取。
- 研究報告原檔在私人 GPT2WEB 儲存庫的專用分支；網站經後端簽發的兩分鐘連結下載，PAT 不會到前端。
- Prompt、模型、服務商、分類、收藏／封存、研究正文與來源等索引仍由私人 Supabase 資料庫提供。新媒體與報告都不經 Supabase Storage 暫存；既有檔案搬移後 Storage 已清空。

外掛安裝包與維護文件位於擁有者的私人 [GPT2WEB 儲存庫](https://github.com/Novel-1234/GPT2WEB)，需有相應 GitHub 存取權限。一般網站使用不需填 PAT 或安裝本機上傳工具。
